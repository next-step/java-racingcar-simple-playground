# 🚗 자동차 레이싱 게임

# 프로젝트 개요
이 프로젝트는 간단한 자동차 레이싱 게임이다.
여러 대수의 자동차가 경주를 하며 최종적으로 가장 멀리 이동한
자동차들이 우승하는 게임이다.

## 기능
- 이름을 가진 각 차량을 등록할 수 있다.
- 여러대의 자동차가 경주를 한다.
- 각 차량은 랜덤한 숫자를 기반으로 이동한다.
- 우승자 리스트를 구할 수 있다.

## 게임실행방법
1. 사용자는 (,)를 이용해 이름을 가진 차량 n대를 만든다.(이름은 최대 5자) 
2. 사용자는 게임의 턴 수를 입력한다.
3. 게임을 실행한 후, 우승자들을 찾는다.

## 고민 정리 📝

### 1. 차량의 이름 조건 검증을 static 메서드로 했는데 맞는 방법일까?
- `CarValidator` 클래스는 유틸 클래스로서 역할이 애매하다.
- `Car` 클래스에서 직접 검증하는 것이 더 적절하다.
- `Car` 객체에 검증 로직을 포함하면 유지보수와 가독성이 좋아진다.

---

### 2. 게임의 조건을 검증하는 로직은 Controller에서 해야 할까, Model에서 해야 할까?
- 게임의 조건 검증은 **Model에서 처리하는 것이 적절**하다.
- 이렇게 하면 게임 검증 로직이 변경되었을 때 유지보수가 쉽다.
- **Controller의 역할은 Model에서 발생한 예외를 받아 적절한 흐름으로 제어하는 것**이다.
- 사용자의 입력을 검증하는 경우는 Controller에서 해도 괜찮을 것 같음.

---

### 3. `Game`이 Controller의 역할을 하도록 만드는 것이 옳을까?
- `Game`이 **게임의 핵심 로직을 담당**하기 때문에 흐름을 제어하는 `GameController`를 따로 만드는 것이 좋다.
- `Game`은 **도메인 로직**을 담당하고, `GameController`는 **입력과 흐름 제어**를 맡도록 분리하는 것이 적절하다.

---

### 4. `Game` 객체와 구별되는 `GameController`를 구현하다 보니, 어디까지가 Controller이고 Model인지 헷갈린다.
- **Model**: 게임의 핵심 로직 (`Game`, `Car` 등)
- **Controller**: 게임의 진행 흐름을 조율 (`GameController`)
- **View**: 결과를 출력하는 역할

---

### 5. 객체를 주입할 때 기준을 어떻게 정해야 할까?
- 차량마다 다른 움직임 전략을 가질 수도 있고, 동일한 전략을 가질 수도 있음.
- "해당 객체를 가장 많이 사용하는 곳"을 기준으로 주입하는 것이 좋음.
- 즉, `MoveStrategy`가 각 `Car`에 따라 달라야 한다면 `Car`에 주입하고,  
  전체 게임에서 동일한 전략을 적용해야 한다면 `Game`에 주입하는 것이 적절하다.

---

### 6. `new Car()`를 통해 차량을 생성하면 Controller에서 차량을 만들게 되는데, 이 방법이 적절할까?
- **Controller가 직접 `new Car()`를 호출하는 것은 MVC 패턴을 위반할 가능성이 있다.**
- 대신 **`createCar()` 같은 Factory 메서드를 활용하면 가독성과 유지보수성이 좋아진다.**
- 만약 게임의 규모가 더 커진다면 `Factory` 클래스를 별도로 만들어서 생성하는게 좋아 보임.

---

### 7. `split()`을 통해 차량의 이름을 나누는 것은 MVC 패턴에서 누구의 역할인가?
- **입력 데이터를 처리하는 부분이므로 `Controller`에서 수행하는 것이 적절하다.**
- Controller가 받은 입력을 `List<String>` 형태로 변환한 뒤, `Game`에 넘겨주는 방식이 깔끔하다.

---

### 8. 게임을 시작한 후 턴마다 데이터를 View를 통해 출력하는 방법은?
- **이벤트 기반, 멀티 스레드 등의 방법이 있지만, 간단한 게임에서는 `CarController`에서 직접 처리해도 무방하다.**
- 즉, `CarController`에서 `game.start()`를 호출하고,  
  **각 턴이 끝날 때마다 View를 통해 현재 상태를 출력하는 방식**이 가능하다.
